## 问题 1：绘制基准面上下颠倒 —— 已确认并修复

### 我原来的判断错在哪里

M0 时我从 KiCad 导入器看到 `ScalePos` 对 Y 取负，推断"文件 Y 向下、需要取负"。
这个推断有两处漏洞：

1. KiCad 的**板坐标系本身是 Y 向下**的。导入器把源数据映射到 KiCad 的板坐标时取负，
   恰恰说明**源数据的 Y 向上**——我把方向搞反了。
2. 我当时没有做端到端的视觉验证，只验证了"尺寸对不对"。上下翻转不改变尺寸，
   所以尺寸检查全部通过，问题被掩盖了。

### 决定性证据：渲染真实工程

你机器上有真实的嘉立创艺术板工程。我把它们的铜层图元**按文件原始坐标**渲染，
不做任何 Y 变换：

- 直接映射（Y 值大的画在下方）→ 文字 **上下颠倒**
- 取负映射（Y 值大的画在上方）→ 文字**正立可读**，凤凰图案正立

这直接证明：**文件 Y 增大方向是向上的**，与设计坐标系一致。

三条佐证：

| 证据 | 内容 |
|---|---|
| KiCad 导入器 | `ScalePos` 取负 → 源数据 Y 向上（因为 KiCad 板坐标 Y 向下） |
| 尺寸标注布局 | 宽度标注在板子 −Y 侧、高度标注在 −X 侧；X 向右为正，则配对布局意味 +Y 向上 |
| 你的实测反馈 | 生成的板子上下镜像 |

### 修复方式

新增唯一常量，所有 Y 变换集中于此：

```python
# pcbart/units.py
FILE_Y_IS_UP = True
Y_SIGN = 1.0 if FILE_Y_IS_UP else -1.0

def y_from_file(value): return Y_SIGN * value
def y_to_file(value):   return Y_SIGN * value
```

原先散落在 `primitives.py` 各处的 `-unit_to_mm(value)` 全部替换为
`unit_to_mm(y_from_file(value))`。要改回只需翻转这一个布尔值。

## 问题 2：竖直边倾斜 —— 已定位并修复

### 根因

两条原因叠加：

1. **位图轮廓是阶梯状的**（每个像素一级台阶）
2. **Douglas-Peucker 把整段阶梯拟合成一条斜线**

实测数据（字母 P，竖直边）：

| 阶段 | 与竖直的偏差 |
|---|---|
| 原始轮廓 | **0.000°**（阶梯本身完全正交） |
| DP 简化后 | **0.331°** |

0.331° 在 71.8mm 的边上就是 0.41mm 的横向偏移——肉眼可见。
水平边更严重，最多偏到 **13.5°**。

### 修复

新增两级吸附，在简化之后执行：

**轴向吸附** `snap_to_axes()`：与轴向夹角在容差（默认 5°）内的边，
绕自身中点旋转到精确轴向。

**坐标聚类** `snap_coordinates()`：把差值小于容差（默认 0.75px）的顶点坐标
归并到同一值，消除残余抖动。

### 效果

| 边 | 修复前 | 修复后 |
|---|---|---|
| 竖直边 | 0.331° | **0.000°** |
| 水平边（4 条） | 最高 13.5° | **0.000°** |
| 水平边（剩余 1 条） | −13.5° | −13.5° |

最后那条保留的斜边是**字母 P 碗部圆弧的真实切线**，字体本身如此，不应被拉直。

### 一个必须避开的陷阱

**吸附不能作用于圆**。把圆上任何落在轴向容差内的点拉到轴上，会把圆压成
圆角方形，半径也随之胀大。实测中圆外半径被错误放大到 30.196mm（应为 30mm）。
现在的顺序是：**先判断是否圆，是圆就跳过吸附**。

## 问题 3：圆应当用圆形工具 —— 已实现

原实现把圆环输出成 72 个顶点的多边形（"折线拟合"）。现在识别出圆后，
写成 EasyEDA Pro 原生的 `CIRCLE` 路径形式：

```json
{"type":"POLY", ...}||{"layerId":11,"width":4.9213,
  "path":["CIRCLE", 0, 0, 1190.9], ...}
```

识别方法：计算多边形的**面积质心**与各顶点半径，若最大径向偏差
低于容差的 3% 则判为圆。圆角方形、腰形孔的偏差远超此值，不会被误判。

效果（60mm 圆环）：

| | 修复前 | 修复后 |
|---|---|---|
| 外框 | 32 顶点折线 | **CIRCLE** |
| 内洞 | 32 顶点折线 | **CIRCLE** |
| 点数 | 1360 → 60 | 1360 → **2** |

顺手修掉一个我自己引入的 bug：圆心被平移了两次（`main_ring` 已平移过，
检测后又加了一次偏移），导致圆被移到 (−40, 40) 而不是原点。

## 问题 4：内洞未挖掉 —— 需要你做一个对照实验

### 我查证到的

1. **规范里没有板框专用图元**。板框就是 layer 11 上的普通图元，
   镂空只能靠几何关系表达。
2. **KiCad 导入器**把 layer 11 映射到 `Edge_Cuts`，然后调 `ConnectBoardShapes()`
   合并所有边——**依据几何连通性/包含关系，不看绕向**。
3. **FILL 记录的绕向不一致**（实测 27 个 CCW、48 个 CW，全是单环），
   无法作为规则依据。之前文档里"外框 CW / 内洞 CCW"的结论**证据不足**，
   已在代码注释中降级说明。

关于你说的"切割环"：那说明编辑器**识别出了内环**（所以有视觉反应），
但把它当作贴附在板面上的轮廓，而不是挖穿。这与"layer 11 上的独立环
默认只表示外形、不表示镂空"一致。

### 我的判断

最可能的原因是：**layer 11 上的孤立内环不会被当作镂空**。
但是我没有可靠来源能证实某种写法一定有效，所以不再猜——我做了一个对照实验包。

### 请你做的验证

`out/` 下有四个文件，表达同一个 60mm 圆环（36mm 孔），区别只在编码方式：

| 文件 | 编码方式 | 预期 |
|---|---|---|
| `cutout_A_separate_rings.epro2` | layer 11 上两个独立闭合折线（当前做法） | 若包含关系有效则挖空 |
| `cutout_B_slot.epro2` | 一个 "C" 形轮廓，带 3mm 开口，**没有封闭内环** | 开口明确，必然挖空 |
| `cutout_C_circle_pair.epro2` | layer 11 上两个原生 `CIRCLE` | 同 A 但几何精确 |
| `cutout_D_keepout_region.epro2` | 外轮廓 + layer 11 上的 `REGION` 标记挖空区 | 若用禁止区驱动则挖空 |

请逐个打开看 3D 预览，告诉我**哪个（些）能真正挖空**。

**B 方案是最保险的兜底**：它是一个"断开的环"，用锣刀一刀就能加工出来，
没有任何歧义。如果 A 和 C 都失败而 B 成功，我就把默认输出改成断口环——
这对加工反而更真实（真实锣边本来就要留一个下刀口）。

细节记录在 `out/cutout_variants` 的生成脚本 `tools/make_cutout_variants.py` 里。

## 教训

**尺寸正确不等于几何正确。** M0 的验收标准只有尺寸，而上下翻转、边倾斜
这两类缺陷都不改变尺寸，所以全部通过了测试却仍然错了。往后的验收必须包含
**视觉验证**：渲染出来看一眼，比任何数值断言都直接。

这也是为什么我一直保留 `tools/render_board.py`——它能在不打开 EDA 的情况下
把坐标系的真相画出来，这次正是它定位了问题 1。
