# M2 开孔方案（实测确定）

> 日期：2026-09-17
> 依据：用户对四种编码方案的实机测试结果

---

## 一、结论

用户在 EasyEDA Pro 里逐个打开四种编码，**只有 B（开槽）能真正开孔**，其余三种
（独立内环、原生 CIRCLE 内环、REGION 标记）都只是在板面上画了一个圈，
3D 预览里材料没被挖掉。

用户同时提供了一条关键替代方案：**纯圆形开口可以用焊盘实现**，
把焊盘直径和钻孔直径设为相同值，就得到一个没有铜环的圆形通孔。

现在两种机制都已实现，按孔的形状自动选择：

| 孔的形状 | 编码方式 | 效果 |
|---|---|---|
| 圆形 | `PAD` 图元，孔径 = 焊盘径 | 真正的圆通孔，可金属化或非金属化 |
| 非圆形 | 开槽轮廓（通道连通到板边） | 单一简单多边形，材料真实切除 |

---

## 二、为什么内环不生效

layer 11（Board Outline）上的**孤立内环只会被绘制，不会被切除**。
编辑器把它当作板面上的一个装饰性轮廓。

这和"真实工程里查不到内环"是吻合的——我分析过的四个嘉立创艺术板工程，
它们的板框全部是单条外轮廓，没有一个用内环表达镂空。

规律是：**layer 11 决定板的边界，但只有与边界连通的部分才会被切掉。**
所以要让材料消失，必须让"要挖掉的部分"与"板外"连通。

## 三、开槽（B 方案）

### 几何做法

把内洞用一个窄通道连到板边，于是整个轮廓从"O"形变成"C"形——
**一个没有内环的简单多边形**。

用 Shapely 实现：

```python
p_outer, p_hole = nearest_points(outer.exterior, hole_poly)
# 沿最近点方向，向内外各延伸 margin，保证切口完整贯通
channel = LineString([start, end]).buffer(width / 2, cap_style="flat")
result = outer_poly.difference(unary_union([hole_poly, channel]))
```

### 一个必须注意的坑

通道**必须向两端都延伸**。只向外延伸（到边界为止）会在边界处留下发丝宽的
残留材料，内洞依然封闭——实测时正是这个原因导致 `interiors=1`，
开槽静默失败。现在两端各外延 `margin_mm`（默认 1mm）。

### 这同时符合真实加工

开槽不是取巧：**锣刀必须有个下刀口才能切出封闭区域**。所以 C 形口是
物理上更真实的表达，嘉立创加工时本来就是这样走的。

### 参数

`--channel-width`（默认 1.0mm）是通道宽度。太窄锣刀进不去，太宽影响外观。
嘉立创最小锣边宽 0.2mm，1.0mm 留了充足余量。

如果通道把板子切成两块，会抛出明确错误而不是产出废板：

```
开槽把板子切成了 2 块；内洞离板边太近，请减小通道宽度
```

## 四、圆孔用焊盘

### 做法

```json
{"type":"PAD"}||{
  "layerId": 12,                                          // 多层 = 通孔
  "num": "1",
  "centerX": 0, "centerY": 0,
  "hole":       {"holeType":"ROUND","width":787.4016,"height":787.4016},
  "defaultPad": {"padType":"ELLIPSE","width":787.4016,"height":787.4016},
  "plated": false,
  "padType": "NORMAL"
}
```

关键点：**焊盘直径必须等于钻孔直径**，否则会留下一圈铜（环宽），
那就不是纯粹的切口了。

### ⚠️ 形状字段必须是对象，不能是数组（2026-09-18 修正）

第一版实现按官方规范正文把两个字段写成了位置数组：

```json
"hole":       ["ROUND", 787.4016, 787.4016],     // ❌ 编辑器静默丢弃
"defaultPad": ["ROUND", 787.4016, 787.4016]      // ❌
```

后果非常隐蔽：**文件能正常打开、板框正常显示、不报任何错，但焊盘整个消失**，
3D 里看不到任何孔。用户实测四个变体文件全部只有圆形板框、没有开孔，
就是这个原因。

判据来自 EasyEDA Pro 自己写的数据：客户端本地缓存里有 1009 条它生成的 `PAD`
记录（版本 3.2.175），**没有一条使用数组形式**，全部是对象：

```json
"hole":       {"holeType":"ROUND","width":36,"height":36},
"defaultPad": {"padType":"ELLIPSE","width":60,"height":60},
"padType": "NORMAL",
"plated": true
```

配套字段也与规范正文不同：`padType` 是字符串 `"NORMAL"` 而非数字 `0`，
`plated` 是布尔值而非 0/1。**以编辑器实际写出的数据为准。**

同样的坑还影响了 `pad_*` 之外的样本：`m2_ring.epro2` 是圆环图，它的中心孔一直
是缺失的。

### 防回归

这一缺陷能潜伏，是因为当时没有任何一层会检查焊盘：

- 单元测试只断言自己写出的数组，自己写自己读，互相印证错误
- Node 独立校验器只解析 layer 11 的板框，`PAD` 记录根本不进它的视野
- 渲染工具同理，画不出不存在的东西

三处都已补上：

| 位置 | 现在的检查 |
|---|---|
| `tests/test_holes.py` | 断言 `hole` / `defaultPad` 是 dict，`padType` 是字符串 |
| `tools/verify_epro2.mjs` | 解析 PAD，拒绝数组形式、拒绝有铜环、拒绝孔超出板框 |
| `tools/render_board.py` | 画出焊盘并挖出钻孔，可直接肉眼验收 |

**教训与 M0 的"插错文档段"同源：能打开 ≠ 内容生效。** 这次的漏洞在于独立校验器
只覆盖了板框，覆盖范围之外的图元等于没有第二意见。

## 五、自动策略

`--hole-strategy` 控制，默认 `auto`：

| 取值 | 行为 |
|---|---|
| `auto` | 圆孔钻孔，其余开槽（推荐） |
| `pad` | 全部走钻孔，非圆孔用最大内切圆近似 |
| `slot` | 全部开槽，包括圆孔 |
| `outline` | 旧行为（不切），只用于对照 |

实测：

```
圆环   -> cutouts: 1 drilled, 0 slotted (auto)   外圈 CIRCLE + 1 个 PAD
字母 P -> cutouts: 0 drilled, 1 slotted (auto)   单一 C 形轮廓
```

字母 P 的开槽效果（渲染图 `out/check_slit.png`）：

如果哪天又写回了不生效的内环或数组形式的焊盘，这一步会立刻报出来。

## 七、字段默认值（已实测确认）

用户在 EasyEDA Pro 中逐个打开三个变体，结果全部符合预期：

| 文件 | layerId | plated | 实测结果 |
|---|---|---|---|
| `pad_1_multi_unplated.epro2` | 12（多层） | false | ✅ 干净圆孔，采用为默认 |
| `pad_2_multi_plated.epro2` | 12（多层） | true | ✅ 同样出孔，金属化可用 |
| `pad_3_layer0_unplated.epro2` | 0（规范示例值） | false | ❌ 无效，0 不是合法层 |

**锁定**：`layerId = 12`、`num = "1"`、`plated` 默认 `false`。
规范正文示例中的 `layerId: 0` 被实测证伪。

`num` 用 `"1"` 而非空串：编辑器自己写出的焊盘编号都是非空字符串，
空串有被判为无效焊盘的风险。
