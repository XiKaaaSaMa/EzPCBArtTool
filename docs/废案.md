## 一、SVG 矢量图导入（2026-10-13 调研，暂停）

### 为什么提出（技术动机）

现在所有图片都要走「位图 → 掩膜 → 描摹成多边形」这条路：

- 细线在矢量化里丢 **16–19%**（方案 A 的遗留问题，见 `PROGRESS.md`）；
- 曲线只能靠短弦逼近（VTracer 弧拟合目前只用于阵营 logo，`export.py:317`）。

如果素材本来就是矢量（logo、Illustrator / Inkscape 画的线稿），
直接读几何可以完全绕开描摹损失，两个写作者还能写**真圆弧**。

### 调研结论：可行，底座比预想现成

1. **两个写作者本来就懂矢量**（实测依据，不是纸面能力）：
   - `.epro2`：`primitives.py:8` 的路径语法就是「类 SVG path」
     （`L` 折线 / `ARC` 两点弧 / `CARC` 圆心弧 / `C` 三次贝塞尔 / `R` / `CIRCLE`），
     `geometry.arc_ring_to_path()`（`geometry.py:307`）把带弧的环写成
     `["ARC", sweep, x, y]`；`POLY` 自带线宽字段（板框与模板装饰都在用）。
   - Gerber：`gerber.py:257` 区域走 G36/G37；`gerber.py:279` 带弧区域用
     `G75` + `G02/G03` 写**真弧**；描边走光圈线。
   - 现成证据：模板固定装饰（FILL 区域 + 50 条描边线）与阵营 logo
     （spline→弧，一路写进 `.epro2` 和 Gerber）都是已实测的。
2. **`ImagePlacement` 是天然载体**：选中 / 拖动 / 旋转 / 翻转 / 取景 /
   组合 / 撤销 / 草稿全部是同一套机制，且草稿与撤销是**反射式序列化**
   （`draft.py:108` 按 dataclass 字段，无白名单）—— 新增字段**零改动**。
   → 不发明新元素类型，`draft.py` / `undo.py` / 工程栏 / 组合全部不动。
3. **仓库里已有半个解析器**：`vtrace.py` 的 path 解析（`:103`、`:211`）与
   三次贝塞尔→弧拟合（`_arc_for_cubic:393`，含三条已踩过的结论：
   每段曲线一个弧、退化判据用**比例**（20× 图形对角，`:763`）、
   极值点必须保顶点）。但它只认 VTracer 输出的**绝对 M/L/C/Z**，
   离通用读取器的差距见下面的范围表。
4. **画布有直接画 QPainterPath 的先例**：`design_canvas.py:3120`
   `_paint_decoration_group`（屏幕路径按视图缓存）。
5. **环境（2026-10-13 本机实测）**：没有任何 SVG 解析库
   （svgelements / svgpathtools / cairosvg 全缺）；QtSvg 在（图标渲染在用），
   但它**读不了超长路径**（历史实测 55 万字符 → Invalid path data），
   只能当降级兜底；`vtracer` 在。
   → 候选解析库 **svgelements**（MIT、纯 Python 单文件、零依赖，
   支持相对/平滑命令、圆弧、transform、viewBox、单位、基础 CSS；
   最后发版 2023-08）。

### 为什么停（用户 2026-10-13 的决定）

用户原话：「导入矢量图之后没办法编辑图像和提取线稿？那这一步暂时不做了」。

**准确的边界（重启时别记串）**：

- **对象本身是可编辑的**：导入后与图片同权 —— 移动 / 缩放 / 旋转 / 翻转 /
  换层 / 取景 / 组合 / Ctrl+Z，一样不缺。
- **不接位图处理链**：读法（填充色块 / 描边+填充 / 纯线条）、降噪、两色、
  板画、线稿重绘**都用不上** —— 它们描述的是「位图怎么处理」，
  而矢量导入直接成几何、不产生位图。所以「从 SVG 提取线稿」这条不适用。
- 若确实要「提取线稿」，唯一路线是**先把 SVG 光栅化、再当图片走现有流程**
  （原方案 Phase 3 的扩展），代价是回到描摹损失、失去矢量的全部好处。
  → **重启时应先问用户要哪一条**。

### 重启时的方案（2026-10-13 版，原样保留）

#### 数据流

```
.svg ──pcbart/svg_import.py（新，Qt-free）──▶ VectorArt
   填充：ArcRing 列表（带弧）/ 点列      { mm、居中、Y 向上 }
   描边：折线 + 线宽 + 是否闭合
        ├─ 导入时写归一化几何缓存（沿用 lineart 的 cache_dir 约定）
        ├─ 画布：QPainterPath 直接画
        ├─ .epro2：填充 → FILL（带 ARC）；描边 → POLY + width
        └─ Gerber：填充 → G36/G37 区域；描边 → 光圈描线
```

placement 复用：新字段（建议 `vector_path` 指向缓存几何）、`kind="svg"`；
`path` 仍指向用户 .svg 原件（来源/报错用）。几何地位与 lineart 的
`processed_path` 一致（原件挪走项目还能用）。
尺寸默认：文件声明了物理单位就 **1:1（mm）**，没有就按图片规则
**最长边 76.2 mm**；两种都能在图片属性面板里改，不新增对话框。

⚠️ SVG **不走预处理面板**（读法/降噪/两色/板画对它是死控件，
违反「控件必然有效」的界面约定）。导入入口 = 拖入 `.svg` +
拖放区过滤器放行（`gui_mockup.py:1041`）、拖拽入口（`:1061`）。

#### 支持范围（v1）

| SVG 特性 | 处理 |
|---|---|
| `M/L/H/V`（含相对、隐式重复） | 折线 |
| `C/S/Q/T` | 采样后**拟合圆弧**（复用 vtrace 的三条结论） |
| `A`（rx≈ry） | 真圆弧（`ArcRing` 的 sweep） |
| `A`（椭圆弧 rx≠ry） | 按弦高容差采样（Inkscape 椭圆转路径即此） |
| `rect/circle/ellipse/polygon/polyline/line` | 转 path；圆/椭圆进圆弧环 |
| `transform`（matrix/translate/scale/rotate/skew） | 累积进几何 |
| `viewBox` + 物理单位（mm/cm/in/pt/px） | 映射到毫米；无单位按 CSS 96dpi |
| `fill` + `fill-rule`（nonzero/evenodd） | 包含树 + 奇偶/绕向 → 外环+孔（shapely 建树，`normalize_arc_polygon` 定绕向） |
| `stroke` + `stroke-width` | 原生线（见下「描边 A/B」） |
| `opacity` / `stroke-opacity` / 渐变 / 图案 | **不支持 → 报告** |
| `text` / `image` / 滤镜 / 裁剪路径 / 蒙版 | **不支持 → 报告**（后续可 QtSvg 光栅化兜底） |
| `dasharray` | v1 报告不支持 |

⚠️ 两个必须记住的默认值：**没写 `fill` 的路径默认是黑色填充**（不是不填充）；
`display:none` / `visibility:hidden` 的元素要跳过。

#### 描边怎么落地（重启时要用户拍板）

| | A：原生线（**当时推荐**） | B：转成填充（buffer） |
|---|---|---|
| `.epro2` | `POLY` + width（模板装饰同款） | FILL 区域 |
| Gerber | 光圈描线（模板装饰同款） | G36/G37 区域 |
| EDA 里形态 | **可编辑的线段对象**、顶点少、文件小 | 填充区域 |
| 代价 | 接头/端头形状随渲染器（圆头近似），要在报告里说明 | 顶点膨胀 |

选 A 的理由：模板装饰已用这条通道在真实板子上跑通（铜层+丝印层都有先例）；
用户对线稿表达过「图片/线对象比填充区域好编辑」的偏好。

#### 分阶段

- **Phase 1（核心，约一轮半）**：解析器 + 填充/描边 + placement 接入 +
  画布 + 两个导出 + 导入报告；含 CSS 类、`<g>`、`<use>` 展开。
- **Phase 2**：`dasharray`、椭圆弧拟合优化、跨文件回归调参。
- **Phase 3（可选）**：彩色丝印模式（光栅化后嵌 OBJ）；
  不支持特性 → 光栅化兜底。

#### 验证计划（按项目规矩）

- 单测（Qt-free）：命令原子用例、transform 累积、viewBox/单位换算、
  fill-rule 嵌套、圆弧 sweep 正负、Y 翻转。**用不对称图形测**
  （对称图形测不出翻转/退化）。每条修复做**注入验证**。
- 极端输入：空 SVG、只有 `<defs>`、单点路径、1px 线宽、超大路径
  （顶点数/耗时上界，先量后改）、全 `display:none`。
- 第三方回读：Gerber 走 `gerbonara` 量包围盒与逐层；`.epro2` 走
  `tools/verify_epro2.mjs`。
- 视觉验收：画布截图 + 真实文件（`out/` 里有现成的 VTracer SVG 可先用）。
- 无素材库环境 0 failed；测试不碰真草稿库；产物进 `out/<日期>test/`。

#### 风险（预埋）

- **Y 翻转 + viewBox 偏移 + transform 累积**三者叠加，错一处就是镜像/偏移；
  判据只能靠不对称图形 + 与渲染器逐点比对。
- **顶点数失控**：复杂 SVG 可能几十万顶点；QtSvg 已证明读不了超长路径，
  画布走自己的几何，但上界与报告仍要有。
- **弧的退化判据必须用比例**（`MAX_ARC_RADIUS_RATIO`，20× 图形对角），
  绝对毫米会随分段粒度失效（已踩过）。
- 细描边 / 细颈接现有工艺校验 warning，不许静默。
- `skew` 会把圆变椭圆，拟合要能承认「这不是圆」。
