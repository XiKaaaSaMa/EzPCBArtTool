```
图片 → 去噪 → 二值化 → 轮廓提取（含内洞）

```

## 二、三个关键决策

### 1. 内洞必须保留

字母 P 的字腔、圆环的中空——这些是板子的真实镂空。OpenCV 的
`RETR_TREE` 会返回父子层级，**按层级深度奇偶性判断是外框还是内洞**：

- 深度为偶数 → 实体（最外层，或内洞里的岛）
- 深度为奇数 → 内洞

如果用 `RETR_EXTERNAL`（只取最外层），内洞会被静默填实，输出的板子是错的。
所以默认模式是 `with-holes`，且这个行为有专门的测试覆盖。

### 2. 简化不是可选项

位图轮廓是**每个边界像素一个顶点**。实测：一个 400×400 的圆环图，
原始轮廓 1360 个点。直接写进文件会是几 MB 的 JSON，专业版打开和编辑都会卡。

Douglas-Peucker 简化后：

| 图形 | 原始点数 | 简化后 | 比例 |
|---|---|---|---|
| 圆环 | 1360 | 60 | 4.4% |
| 字母 P | 773 | 29 | 3.8% |
| 星形 | 961 | 12 | 1.2% |

`simplify_tolerance_px` 直接暴露为参数，默认 1.5 px。
这就是"保真度 vs 文件大小"的调节旋钮。

### 3. 工艺补偿用 Shapely，不手写

`offset_mm` 通过 `shapely.buffer` 实现，正向放大轮廓（可用来保证最小线宽），
负向收缩（可用来让板子从图形内缩）。

**为什么不手写**：M2 星形那一步我手写的线段相交判定把"共线但不重叠"
误判成了相交。轮廓点上千时手写几何判定必然出错。Shapely 是经过验证的
工业级实现，这类判断必须交给它。

### 4. 细颈检测：试错两次才定下来

艺术板容易描出细长的"脖子"，太细会在锣边或搬运时断裂，所以要检测。
这个指标我先后写了三版，前两版都是错的：

**第一版：形态学开运算的面积差。**
腐蚀会同时把凸角磨圆，而磨圆在任何半径下都会损失面积。一个 10×10mm 的
正方形在 r=0.8 时就已经损失超过 0.5% 面积，于是被上报成 1.5mm 厚。**错**。

**第二版：中轴线的距离变换。**
这是教科书式的"局部厚度"定义——中轴线上每点到边界距离的二倍。
但它对五角星失效：星形的凹角处，中轴线会延伸进尖角，而尖角处宽度
**本来就趋于零**。结果每个星形都会被判为细颈。**也错**。

**第三版（当前）：腐蚀的拓扑判据。**
对半径 r 二分，观察形状何时**裂成多块或消失**，此时 2r 就是最窄通道宽度。
- 均匀条状 → 报出条宽
- 哑铃形 → 报出中间细颈，而非两端
- 五角星 → 不报警（凹角腐蚀掉但主体不裂开）
- 字母 P → 报出较大值，含义是"没有细颈"

代价是：**没有细颈时返回的是最宽通道，会高估**。但这个问题问的是
"有没有地方细到会断"，返回一个大数等于回答"没有"，语义上是对的。
函数名和文档都按这个语义写，避免误用。

**已知缺口**：从厚主体上伸出的细长凸起检测不到（腐蚀掉凸起后主体仍连通）。
细颈和整体偏薄这两种真正会断的情况已覆盖。

## 三、重要修正：多边形绕向

### 规范说的和实际不一样？

官方规范原文："复杂多边形…固定第一个多边形顺时针，表示外框，后续所有多边形逆时针，表示内洞。"

但**在哪个坐标系里说**？文件里 Y 向下，设计坐标系 Y 向上，两者会得出相反的结论。

### 用真实数据判定

我写了 `tools/analyze_winding.py` 分析真实工程，结论明确。取一条 `IMAGE`
记录（真实样本，含外框+内洞）：

```
ring 0: 文件坐标系 CCW(+)  →  设计坐标系 CW(−)    ← 外框
ring 1: 文件坐标系 CW(−)   →  设计坐标系 CCW(+)   ← 内洞
```

（设计坐标系面积：外框 −1873511.9，内洞 +1357522.5）

**结论：规范的"顺时针/逆时针"是在设计坐标系（Y 向上）里说的。**

因为文件存的是 Y 向下，同一组环在原始文件文本里看起来是反的——这解释了
为什么直接看文件字节会觉得和规范矛盾。

### 我原先写错了

`pcbart/geometry.py` 最初实现为 `ensure_ccw(outer) / ensure_cw(hole)`，
正好写反。现在修正为 `ensure_cw(outer) / ensure_ccw(hole)`，
并且有回归测试锁定。

### 板框层为什么不受影响

星形板框用的是设计坐标系 CCW 且渲染正确。原因是**板框的判定机制不同**：
KiCad 导入器把 layer 11 映射到 `Edge_Cuts`，然后调 `ConnectBoardShapes()`
把所有边合并成闭环——它靠**几何包含关系**判断内洞，不看绕向。

所以两种机制都覆盖了：
- **填充/覆铜**（`FILL`/`POUR`）→ 靠绕向区分实体与洞，用 CW 外框 / CCW 内洞
- **板框**（layer 11）→ 每个环是独立闭合曲线，靠包含关系区分

## 四、验证结果

### 端到端实测

| 输入 | 内洞 | 输出点数 | 尺寸 | 校验 |
|---|---|---|---|---|
| 圆环 | 1 | 1360 → 60 | 60.000 × 60.000 mm | 通过 |
| 字母 P | 1 | 773 → 29 | 60.000 × 74.384 mm | 通过 |
| 星形 | 0 | 961 → 12 | 60.000 × 57.438 mm | 通过 |
| 字母 P + 3% 噪点 | 1 | 773 → 29 | 60.000 × 74.897 mm | 通过 |

噪点那一行值得注意：输入加了 3% 椒盐噪声和高斯噪声，但去噪后
**内洞仍正确保留，点数与干净输入完全一致**，尺寸只差 0.5%。

### 独立校验（Node 校验器）

```
board outline: 60.0000 x 60.0000 mm
outline rings: 2
  areas (mm^2): outer=2844.44(CW), hole=1038.85(CCW)
  all holes lie inside the outer ring: ok
VERIFY OK
```

数值与理论吻合：外半径 30 mm → 面积 2827 mm²（实测 2844，多边形逼近的偏差）；
内半径 18 mm → 1017 mm²（实测 1039）。

### 测试覆盖

**175 项测试全部通过**，M2 新增 49 项，覆盖：

- 极性自动判定（深色主体 / 浅色主体两种）
- 内洞保留与丢弃（含单像素针孔过滤）
- 简化效果与形状保真
- Y 轴翻转（图像 Y 向下 → 板框 Y 向上）
- 缩放与长宽比保持
- 工艺补偿（正向放大 / 负向收缩 / 过度收缩报错）
- **绕向回归**（外框 CW、内洞 CCW、岛跟随外框）
- 细颈检测（均匀条 / 哑铃 / 薄片报警；星形与字母 P 不误报）
- 四种图形的端到端有效性

## 五、用法

```bat
:: 从图片生成（保留内洞，宽 60mm）
python tools\make_outline_from_image.py art.png --width 60 --mode with-holes

:: 合成测试图自检
python tools\make_outline_from_image.py --test ring --width 60 --mode with-holes --preview

:: 生成掩膜预览方便调试阈值
python tools\make_outline_from_image.py art.png --width 60 --preview
```

`--preview` 会输出二值化后的掩膜 PNG。**这是排查问题最快的入口**：
如果掩膜里图形就不对，问题在阈值/去噪；掩膜对了但输出不对，问题才在几何阶段。

### 主要参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--width` / `--height` | 100mm | 目标尺寸，两者都给时取较小缩放（保证放得下） |
| `--mode` | `with-holes` | `external` 只取外轮廓（会填实内洞） |
| `--simplify` | 1.5 | 简化容差（像素），越大点越少、越粗糙 |
| `--offset` | 0 | 工艺补偿（mm），正=放大，负=收缩 |
| `--threshold` | `otsu` | `adaptive` 适合光照不均的照片 |
| `--noise` | 0 | `--test` 模式的噪点强度 |
| `--keep-holes` | 关 | 关掉"填实掩膜内洞"，保留真实镂空 |

## 六、已知限制与下一步

**当前限制**：

1. **只输出板框**，还没有铜层落图（M3）
2. 简化会产生折线，没有圆弧拟合——圆形轮廓出来是多边形（60 个顶点）
3. 多个分离的图形时，只有最大的作为主板，其余作为岛处理
4. AI 线稿化（M4）尚未接入

**下一步（M3）**：把图片落到铜层，两种风格——

- **填充风格**：区域直接转复杂多边形 → `FILL` / `POUR`
- **走线风格**：形态学细化求中心线 → 变宽 `LINE` 走线

工艺校验器已就位（`validation.py` 的最小线宽/线距检查），M3 直接复用。
